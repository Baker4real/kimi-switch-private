# 按卡重授权：凭证覆盖的身份门与写序

按卡重新授权（issue #3，2026-08-27 实现）复用设备码授权流程，但目标是一张已存在的账号卡，而不是收进新身份。凭证覆盖落在 `FileBlobProvider::replace_account_blob`，两条决策约束它：

1. **身份门在一切写入之前**：先从新凭证解析官方账号 id（与入库同规则：`parse_metadata` → `primary_id` 回退 `label`），与目标卡不一致或无法辨认时直接失败——库存不写、live 不写、不新增卡。授权结果绝不是「照单全收」，它必须证明自己还是这张卡。
2. **写序固定「先库存后 live」**：库存是唯一真本，先落库；仅当该卡是当前账号才原子写 live（tmp+rename）。严禁在任何路径先把旧 live 回灌库存——那会把刚写入的新凭证盖掉；后续切换的 capture-on-leave 只属于正常路径。

已接受的边界（有意不做防御）：库存写新成功而 live 原子写失败时，会留下 store=新/live=旧 的窗口，其后一次切换会把旧 live 回灌、静默撤销新凭证。触发前提是罕见的本地 IO 故障，即时状态安全（旧凭证仍可用、无锁死、错误已上抛告知用户）。修正它需要改变切换的 capture 策略，代价大于收益；若未来要改，先重开本决策。
