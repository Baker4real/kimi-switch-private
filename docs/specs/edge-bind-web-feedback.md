# Edge 绑定结果网页反馈与到期展示瞬态归因

> GitHub spec issue：Baker4real/kimi-switch-private#177（enhancement + ready-for-agent）。
> 本文件是 #170（`docs/specs/edge-web-binding.md`）的增量规格副本。#170 与 #176 已于 2026-09-23 关闭；真实 Edge 交接不再作为关闭条件。本地测试不写成真实 Edge 已验收。到期展示瞬态仍是 #179，保持调查，不标完成。

## Problem Statement（问题陈述）

用户在 Edge 控制台页完成免粘贴绑定后，注意力仍停留在网页上；绑定结果（成功/失败及原因）只显示在 kimi-switch 窗口里，而该窗口多半被 Edge 挡住，用户无法第一时间看到反馈，需要主动切回应用确认。

另外，2026-09-21 真机重绑验证中出现过一次瞬态：绑定成功后账号卡的会员到期进度条（含「有效期至」文案）消失，当时点「刷新」也未恢复，稍后自行出现。数据层已核实完好（extra 同时保留档位缓存与到期键，CLI 只读列表正常，行组装有测试钉住），真因未定，不应在无证据下写防御代码。

## Solution（解决方案）

扩展现有 Edge 免粘贴绑定闭环（#170 / [ADR-0018](../adr/0018-edge-web-binding.md)，既有回调保持原样）：loopback listener 增加只读 GET `/kimi-switch/web-bind-status?nonce=`。扩展在回调之后轮询该状态，页面脚本只在**带本次挑战的控制台页**渲染轻量 toast。回查成功原因是「绑定成功」；页面 toast 是「绑定成功，可回到 kimi-switch 查看」。失败原因只有「已取消」「等待超时」「无可用网页凭证」「账号身份不一致」；页面 toast 是「绑定失败：」接该句。网页凭证、账号标识与 JWT 不进入页面。真实 Edge 上的显示按 2026-09-23 的决定不再作为 #176 的关闭条件；本文不把它写成已经真机验收。

会员读取失败在回查上是成功。细分状态仍只在 GUI。GUI 对话框与 CLI 的绑定网页登录行为不变。

到期展示瞬态拆独立调查项：先复现归因（附现场自查步骤），真因确定后再拆修复票；本轮不做投机性防御修复。

## User Stories（用户故事）

1. 作为账号库用户，我希望绑定成功时控制台页上直接弹出成功提示，以便不必切回 kimi-switch 确认结果。
2. 作为账号库用户，我希望绑定失败时控制台页上能看到失败原因，以便知道是登错账号、超时还是已取消。
3. 作为登错网页账号的用户，我希望页面提示「绑定失败：账号身份不一致」，以便立即换回目标账号重试。
4. 作为账号库用户，我希望 toast 自动消失，不遮挡控制台页的正常使用。
5. 作为读屏/键盘用户，我希望 toast 以 aria-live 等既有无障碍手法播报，以便非视觉途径也能得到结果。
6. 作为隐私敏感用户，我希望 toast 只含结果与一句中文原因，不含网页凭证、账号标识或 JWT，以便页面不出现凭证。
7. 作为隐私敏感用户，我希望没有绑定挑战的普通控制台页不注入任何 UI、不发任何请求，以便扩展的存在对日常浏览零感知。
8. 作为使用其他 Edge profile 的用户，我希望只有发起绑定的那个挑战页面显示 toast，以便其他 profile 页面不受影响。
9. 作为取消绑定的用户，我希望取消后回查得到终止态（已取消），页面不再显示进行中状态。
10. 作为遇到等回调超时的用户，我希望该超时是可回查的终止态，以便页面提示「绑定失败：等待超时」。
11. 作为重复触发回调的场景，我希望状态回查只反映一次性消费的最终结果，以便重复回调不产生二次提示。
12. 作为 GUI 用户，我希望对话框状态行、重试、手动粘贴兜底行为完全不变，以便网页反馈只是增量而非改动。
13. 作为 CLI 用户，我希望 bind-web 行为零变化，以便脚本与无 GUI 环境不受影响。
14. 作为维护者，我希望状态端点凭 nonce 只读回查、无副作用，以便攻击面不扩大（伪造 nonce 查不到别人的结果）。
15. 作为维护者，我希望扩展静态契约测试钉住「toast 仅挑战页注入、回查只打固定路径、网页凭证与账号标识不进页面」，以便未来改动破坏边界时测试变红。
16. 作为维护者，我希望 Rust broker 测试覆盖状态端点的全部终止态与枚举，以便协议演进有回归网。
17. 作为发布维护者，真实 Edge 下 toast 的实际显示已登记进 #176 矩阵。按 2026-09-23 的决定，该项不再作为关闭条件，且未在已登录 Edge 上执行；静态测试不写成已验收。
18. 作为账号库用户，我希望再次遇到「绑定后会员到期进度条消失」时有 30 秒自查步骤可执行，以便下次出现即抓到现场证据。
19. 作为维护者，我希望瞬态归因票记录两个候选路径（刷新被忙碌早退吞掉后轮询自愈 / 快照组装瞬时缺档位），以便归因有明确分叉可验证。
20. 作为维护者，我希望瞬态在真因确定前不引入防御性代码，以便代码库不积累无证据分支。

## Implementation Decisions（实施决策）

- 状态回查：只读 GET `/kimi-switch/web-bind-status?nonce=`，只凭 nonce，无副作用。200 的 JSON 只有 `result` 与 `reason`。未知、伪造、过期 nonce 都是空正文的 404，彼此不可区分。载荷不含网页凭证、账号标识或 JWT。
- 结果：`pending` / 「等待中」（还没收到回调，或回调已收下但管道结果还没发布）；`success` / 「绑定成功」；`failure` 只有「已取消」「等待超时」「无可用网页凭证」「账号身份不一致」。「等待超时」只对应等回调超时。无法辨认网页身份、账号不存在、其余「绑定失败：…」、目标账号已变化，回查原因都是「无可用网页凭证」。
- 时间窗：短窗口从发布终止态起算。网页状态在绑定管道结算并写完审计之后、额度快照之前发布。成功或失败后再保留 10 秒，然后 404 并关闭监听。回调收下后若一直不发布结果，最多 20 秒后按不存在收场，不报「等待超时」。
- 扩展：只在带本次挑战 fragment 的控制台页 toast，`aria-live`，约 5 秒后消失。无挑战页零注入、零请求。POST 得到 204 后有限轮询，12 次、第一次立即、其后间隔 2 秒，读到终止态即停；12 次都没有终止态时，扩展交回「等待超时」，页面显示「绑定失败：等待超时」。POST 抛错或不是 204 时只短探测已有终止态，3 次、第一次立即、其后间隔 250 毫秒。页面只在读到已发布终止态时提示；空网页凭证的原因是「无可用网页凭证」。pending、404 或连不上不弹 toast，也不合成「等待超时」。
- toast 文案：成功为「绑定成功，可回到 kimi-switch 查看」；失败为「绑定失败：」接回查那句原因。
- 既有回调冻结：fragment、POST `/kimi-switch/web-bind`、JSON 载荷、204 语义不变。回查不扩大伪造挑战面，伪造 nonce 看不到真实会话结果。
- GUI 与 CLI：对话框状态行、忙碌早退、重试分流、手动粘贴兜底保持原有用户可见行为。手动粘贴仍等额度快照才返回。
- 会员读取失败在回查上是成功。细分状态仍只在 GUI，回查原因不单列会员读取失败。
- 窗口起算、枚举与安全考量的决策记录在 [ADR-0018](../adr/0018-edge-web-binding.md)「状态回查」。扩展 README 的安装说明写明：绑定结果会短暂显示在挑战页面。安装、更新、撤销步骤与权限声明不另加打包步骤。
- 到期展示瞬态：独立调查项，不在本 spec 实现范围；调查项内附现场自查步骤（观察 GUI 忙碌态、触发一次重列、运行只读 CLI list 对照 extra、对时间线核对审计事件），产出归因结论后另拆修复票；两个已记录候选：绑定收尾期「刷新」点击被忙碌早退静默吞掉后轮询自愈、快照组装瞬时缺档位（/me 或额度收集瞬时失败下一轮补齐）。

## Testing Decisions（测试决策）

- 只测外部行为，沿用 #170 链已建立的三条既有 seam，不新增测试缝：
  - Rust broker seam：状态端点覆盖成功与四句失败原因；收下后未发布仍是「等待中」；终止态保留从发布起算，窗口结束后与未知 nonce 同为 404；未发布上限后不存在且不是「等待超时」；载荷不含网页凭证或账号标识；伪造 nonce 看不到真实会话结果。
  - 扩展静态契约 seam（vitest 读扩展源文件断言）：toast 只出现在挑战分支；204 后 12 次、间隔 2 秒轮询，耗尽时交回「等待超时」；POST 失败只做 3 次、间隔 250 毫秒的终止态短探测，且该路径不合成「等待超时」；回查只打固定状态路径；网页凭证与账号标识不进页面；无挑战页零注入。
  - GUI seam 回归：现有 webBind 契约测试不变绿转红即为回归信号。
- 真实 Edge 下 toast 实际显示、时序与 Local Network Access 曾登记在 #176。按 2026-09-23 的决定，这些不再作为关闭条件，也未在已登录 Edge 上执行。静态测试不代替该矩阵，也不写成已验收。
- 先例：web_bind.rs broker 测试、edge-extension-contract.test.ts、webBind.test.ts。

## Out of Scope（范围外）

- 修改 GUI 对话框的任何提示、状态行、重试或手动粘贴行为。
- Windows 系统通知、任务栏闪烁、窗口置顶抢焦点等替代反馈渠道。
- 在无挑战的普通页面注入任何 UI 或发起任何请求；扫描其他标签页/profile。
- 网页凭证、账号标识、JWT 进入页面、URL、扩展 storage 或回查载荷。
- 会员读取失败细分状态上网页；会员到期数据源变更。
- 到期展示瞬态的防御性修复（真因未定）；CLI 行为变更；回调协议既有部分的任何调整。
